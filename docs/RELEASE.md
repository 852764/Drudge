# 0.2.0b3 Beta 发布门槛

本次新增统一仓库发现与预算明确的检索，见[仓库搜索](REPOSITORY_SEARCH.md)；新增运行依赖 `pathspec>=1.1.1,<2`，升级时正常安装依赖。此前 b2 的批量读取、临时轮次提示、工具禁用、超时和退出码修复见 [CodeGo 试用记录](DOGFOOD_CODEGO.md)。仍保持 Beta 定位与下列发布门槛。

此版本面向有人审阅的本地开发工作流。目标是可安装、可恢复、可观测的 Beta，不宣称已超过其他 Agent，也不等同于无人值守生产系统的安全认证。

## 发布检查

安装项目运行依赖以及 `setuptools`、`wheel` 后执行：

```powershell
python scripts/release_check.py
```

检查程序不访问模型或读取认证文件，也不提交或推送代码。它会：

1. 检查 Git 索引及未忽略的新文件，排除凭据路径、缓存、数据库、越界链接，扫描高置信度密钥格式；只报告文件名。
2. 执行全部离线 unittest、compileall 和 Git 空白检查。
3. 本地构建 wheel 与 sdist，检查归档内容和必要模块，记录 SHA-256。
4. 新建虚拟环境，离线安装生成的 wheel，在源码目录外验证包来源、版本、CLI、两种 API 的工具回路、计划恢复和终端执行。
5. 在 `build/release-check/run-*/` 写入 JSON 报告、分步日志及构建物；失败返回非零退出码。

虚拟环境通过 `--system-site-packages` 和临时 `.pth` 复用当前 Python 的 `site-packages` / `dist-packages` 运行依赖（兼容由宿主注入依赖目录的情况），不带入源码目录或任意 `PYTHONPATH` 项。wheel 自身重新安装；冒烟脚本复制到构建目录，用 `-I` 运行，并断言所有 Drudge 模块导入文件来自新环境。这验证离线打包完整性，不是完全隔离的依赖环境，也不代替全新机器上的在线依赖解析。

GitHub Actions 在 Windows/Linux 的 Python 3.10、3.13 和 macOS 的 Python 3.13 上运行相同门槛，保存 14 天的结果。新增 CI 配置不代表这些远端作业已经通过；以相应提交实际运行结果为准。发布 tag 或推广稳定版前，要求矩阵全部成功。

## 运维与升级

- 默认 `on_request`：文件修改、终端执行及有风险的网络操作需要 host 审批；非交互调用不会自动批准。可信自动化须显式选择 `--approval-mode auto`。
- 升级前退出 Drudge，备份会话 SQLite 数据库；采用 SQLite 在线备份或同时保留尚未 checkpoint 的 WAL 数据。不要只复制一个正在写入的 `.db`。
- 表迁移为增量，不主动清理旧历史。回退到旧包前保留新库副本；旧程序不会理解新增计划/上下文/输出字段。
- 每次工具输出限制 8 MiB，但数据库还没有总量保留策略；监测磁盘占用，轮换 `DRUDGE_DB_PATH` 并保留需要审计的数据库。
- `/fork` 是会话分支，不是 Git worktree；文件仍共享。并行改动需要另外隔离工作树。
- Windows 同步终端命令退出时清理 Job 内全部后代，不用它承载长期后台服务。
- 终端审批不是 OS 沙箱，批准的命令具有当前账户权限。对不可信仓库使用独立容器/低权限账户；不要把凭据放入模型可读工作区或提交内容。
- SQLite 和 trace 可能保存提示、代码及工具输出；妥善设置本地目录权限和备份访问权限。

## 仍需真实环境验收

离线测试不验证用户的模型账户、代理连通性、线上限流、计费或长时间真实仓库任务成功率。正式推广前用独立样本项目进行一次明确启用的 API 冒烟，再开展真实仓库基准：记录验收成功率、非预期文件修改、耗时、token 和费用，固定任务/模型/预算后再比较。

## 本轮改动

- 原子文件编辑、SHA-256 前置检查、冲突感知撤销。
- 持久化压缩上下文、工具事务恢复和会话分支。
- 准确退出状态、有界输出捕获和持久化分页。
- 计划恢复、验收记录、修订冲突检测与 `/plan`。
- Windows Job Object、连续取消清理、日志设施故障降级。
- 默认交互审批、非法审批模式校验，以及本地/CI 发布检查。
