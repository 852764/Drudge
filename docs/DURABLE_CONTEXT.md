# 长任务上下文恢复与会话分支

本轮解决两个状态丢失问题：摘要压缩只留在内存、恢复时工具结果被追加到错误位置。同时加入从当前工作上下文创建会话分支的能力。

## 持久化上下文检查点

```text
/compact
/status
/resume <session_id>
/history <session_id>
```

启用 SQLite 存储后，手动和自动压缩使用同一套流程：

1. 生成摘要，并保留近期完整工具调用组。
2. 事务化保存工作上下文检查点。
3. 提交成功后才替换内存中的消息列表。

恢复时加载 **最新检查点（通过校验后）+ 该检查点之后的原始消息**，而不是把压缩前的整个历史重新塞回模型。系统提示词仍使用当前工作区、当前 `AGENTS.md`、当前启用 Skill 内容及宿主配置构建。

`messages` 原始历史不删除、不改写，仍供 `/history` 审计。`context_checkpoints` 为增量建表迁移，保存：

- 会话 ID、检查点 ID、原始消息截止 ID；
- 格式版本、完整工作消息 JSON、绑定消息截止位置和元数据的 SHA-256 完整性指纹；
- 压缩 / 工具修复原因、累计 turn 和最近压缩信息。

JSON 同时保留 Chat 工具调用与 Responses `provider_items`。供应商加密 reasoning 仅在相应 API 中继续传递，不送入摘要转录；宿主 `ToolContext` 和审批缓存不属于检查点字段。

检查点损坏或版本不支持时，显示警告并从原始历史恢复。关闭存储时继续使用内存压缩，结果不宣称已持久化。SHA-256 用于检测数据损坏，不是密码学身份认证。

## 过期写入检测

写入新消息、提交检查点和创建分支时，会在 SQLite 写事务内同时比较：

- 最近原始消息 ID；
- 最近上下文检查点 ID。

另一个消费者已经推进同一会话时，当前操作报告冲突，要求重新 `/resume`。这样既防止压缩吞掉另一进程的新消息，也防止旧压缩覆盖一个更新的检查点。

同一 Agent 的模型运行和手动压缩之间互斥；运行期间切换、清空或分叉上下文会报告忙状态。手动压缩可取消，提交前取消不发布新摘要。

这不是跨进程工具副作用的“恰好执行一次”保证。工具已经修改文件、但结果尚未记录时进程仍可能退出，因此恢复必须保守处理未知结果。

## 按协议顺序恢复中断工具调用

旧行为可能产生：

```text
assistant(tool_call A) → user(新请求) → tool(A 的中断结果)
```

现在工作上下文修复为：

```text
assistant(tool_call A) → tool(A 的中断结果) → user(新请求)
```

已记录的工具结果保留；缺失结果标记：

```json
{"interrupted": true, "outcome_unknown": true}
```

这个标记表示**执行结果未知**，不是“肯定未执行”。恢复本身不重跑工具，并提示模型先检查实际状态。该修复既用于重启恢复，也用于当前进程取消后继续下一轮。

孤立 / 重复结果从工作上下文排除，原始审计记录仍保留。补入的中断审计消息和修复后的工作检查点在一个事务内提交，后续恢复不会反复补入同一结果。

## 会话分支：探索不同方案

```text
/fork
/fork approach B
/sessions
/resume <parent_session_id>
```

`/fork` 从**当前工作上下文**创建子会话并切换过去。父会话的历史保持原样，子会话保留已启用 Skills，并记录父会话、消息截止位置及检查点来源。

分支是会话级的，不是 Git worktree：

- **工作区文件仍共享**，没有自动创建磁盘隔离副本。
- 不复制审批缓存、运行 trace、持久任务或文件撤销历史。
- 不重放历史工具调用。
- 切换回父会话不回滚文件；后续编辑仍应使用文件 SHA-256 前置校验。

## 确定性摘要降级改进

摘要模型失败时，确定性摘要保留最初用户要求与最新进展 / 修正，不再只截取最早 20 项。无文本的工具调用也保留工具名称；`error: null` 的成功工具结果不再被误标为失败。

`compact_keep_recent` 要求至少为 1。摘要仍是有损压缩，全部原文保存在原始历史中。
