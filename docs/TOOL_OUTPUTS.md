# 工具状态与大输出分页

本轮改进工具执行结果的准确性，以及长输出的捕获、保存和按需读取。保持 Python 3.10+、Chat Completions 和 Responses 工具协议兼容。

## 1. 退出状态与输出保存是两件事

- 终端退出码为 0 时返回 `ok: true`；仅有 stderr 文本不代表失败。
- 非零退出码返回 `ok: false`、对应 `exit_code` 和错误说明，保留已捕获输出。
- 超时返回失败及 `timed_out: true`；取消保存部分日志后重新抛出取消异常。
- 日志保存失败以 warning 说明，不把已成功执行的操作改判为失败，避免模型为取日志而重复修改文件。
- 旧客户端仍可读取终端结果的 `output`、`exit_code` 字段。

## 2. 分块捕获与限制

stdout、stderr 并发以 16 KiB 块排空，使用增量解码。每路输出保留约 3000 字符的头尾预览。启用会话存储时，使用临时 spool 保留最多 **8 MiB UTF-8 文本**，结束后写入 SQLite。

达到捕获上限后仍继续读取进程管道，避免输出堵塞子进程；完整性标记变为 `complete: false`。小输出正常完成时无需额外持久化。关闭会话存储时只保留受限预览，并在发生截断时说明原文未保存。

捕获对象是解码后的文本：Windows 使用宿主首选编码，其他平台使用 UTF-8；无效字节替换为解码替代字符。这不是二进制原始输出归档。

注意限制的范围：

- 8 MiB 是**每条输出记录**的文本上限，不是整个会话或数据库总上限。
- stdout、stderr 和工具 JSON 原始结果可能分别形成记录。
- 持久化阶段会读取受限 spool，因此不是整个运行期都只占用预览大小的内存。
- 当前没有总存储配额、自动过期或清理命令；日志可能包含项目敏感信息，应按会话数据管理。
- 当前是分块捕获，不代表已实现终端实时 UI 输出、后台作业或操作系统沙箱。

## 3. JSON 结果不再被直接切断

Agent 发送给模型的每条工具结果默认限制为 **10000 个序列化字符**。超过预算时：

1. 尝试保存完整的标准化结果；超过持久化上限则保存其前缀，并明确标记不完整。
2. 返回仍可解析的 JSON，保留成功 / 失败、blocked 和关键操作状态。
3. 正文变为头尾预览，`metadata.truncated` 为 true，`metadata.output_ref` 指向保存的原结果。

预算根据实际 JSON 序列化长度计算，包括引号、换行和控制字符的转义开销。原始结果的其他字段可通过输出 ID 按需读取。若原始 JSON 本身被持久化上限截断，记录的 `kind` 改为 `text`，不将不完整 JSON 宣称为完整文档。

## 4. 两类输出 ID

- `metadata.output_ref.id`：被预览替代的**标准化工具结果 JSON**。
- 终端 `metadata.output_refs.stdout.id` / `.stderr.id`：对应流的**文本捕获**。

如果终端结果本身仍超过模型预算，外层引用指向终端结果 JSON；其中保留各个流的 ID。所有记录也可通过 `/outputs` 查看。

模型使用只读工具：

```json
{"output_id": "<返回的输出 ID>", "offset": 0, "limit": 1000}
```

工具名为 `read_tool_output`。`offset` 从 0 开始，按 Unicode 字符计数；`limit` 为 1～1000，默认 1000。用返回的 `next_offset` 继续，直到 `eof: true`。

**`eof` 仅表示读到了已存储文本的末尾。** 原始进程输出是否完整，还要看 `complete`；超时、取消或达到上限都会产生部分捕获。

## 5. CLI 使用

```text
/outputs
/output <id>
/output <id> 1000 1000
```

CLI 显示范围、完整性状态和下一页命令。NUL、ESC 等终端控制字符显示为转义文本，避免在查看日志时执行控制序列；存储内容和模型读取内容保持不变。

## 6. 存储、恢复和权限

新增 `tool_outputs` 元数据表和 `tool_output_chunks` 分块表，迁移不改写已有历史。每块最多 4096 个字符，以 UTF-8 BLOB 保存，支持 NUL 和跨块 Unicode。记录和分块事务化提交；分页仅读取相关块，并校验块 SHA-256。校验用于发现数据损坏，不作为身份认证。

读取同时限定**当前会话和当前工作区**。模型只提交输出 ID 与分页参数，不能指定数据库路径、会话、工作区或 `ToolContext`。分页工具不会被动态工具选择隐藏，且只读读取不需要修改审批。

- 重启 `/resume` 和上下文 `/compact` 不删除输出记录。
- `/fork` 复制会话文本，但不复制输出库访问；父会话旧 ID 需要切回父会话读取。
- 切换会话后的旧 callback 仍绑定原会话，迟到的输出不会写到新会话。

## 7. 进程清理与测试环境

Windows 使用在启动 shell 前建立的 kill-on-close Job Object；owner 正常退出或被终止时，仍在运行的后代也会退出，因此终端工具不支持启动长期后台服务。Job 初始化失败时命令不执行。POSIX 超时/取消使用独立进程组信号；主动脱离进程组的服务不在该清理保证内。清理错误会写入结果 `metadata.warnings` 或取消异常消息，不再静默丢弃；连续取消会等待同一个清理任务完成。

验证真实子进程用例时，应在允许管理自建测试进程的环境中运行。进程生命周期管理不等于操作系统权限隔离。临时输出文件创建失败时，工具退化为有界内存预览并报告警告，不因日志设施失败而阻止原命令。
